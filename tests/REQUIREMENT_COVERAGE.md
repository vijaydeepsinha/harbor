# Requirement coverage — MCP governance

Every governance requirement (IDs defined in [`TEST_ARCHITECTURE.md`](../TEST_ARCHITECTURE.md) §2,
derived from `docs/poc/requirements-aug28.md` and `docs/code-mode-governance.md`) mapped to the
executable tests that prove it. "E2E" = `tests/e2e/governance/*.test.ts` (real MCP calls over
HTTP against the production image, or `--local` host processes); "Unit/Int" = the vitest layers
under `tests/unit` and `tests/integration`; "Postman" = folders of
`postman/mcp-governance.postman_collection.json`; "CI" = the workflow that runs it.
Status reflects the release-readiness local run on 2026-11-21: E2E 157/157
(15 files), Postman 118 requests / 232 assertions, 389 passed in total; the
current `npm test` baseline is 73 files, 838 passed + 1 skipped.

PR #8 follow-up regressions: `tests/integration/persistence-failures.test.ts`
covers RG-003/RG-005 settlement failures before and after completion writes,
failed lock release, unreadable read-back, truthful status metadata and no
repeated backend side effects. `tests/unit/governance-rules.test.ts` covers
RG-009 with missing, non-numeric, zero and negative claimed current bids in
the example policy. `tests/unit/url-utils.test.ts` verifies that arbitrary
query values and fragments do not appear in diagnostic URLs.
